# Фото для сайта «Хлоя»

Все фото на сайте — реальные снимки студии из карточки организации на
Яндекс Картах: <https://yandex.ru/maps/org/khloya/34375427491/gallery/>
(62 фотографии, теги «Товары», «Внутри», «Снаружи», «Вход»).

## Как пересобрать

```bash
node tools/photos/fetch_photos.mjs     # скачает оригиналы в _tmp_photos/raw/
python tools/photos/build_photos.py    # нарежет и сожмёт в assets/photos/shop/
node tools/photos/verify_photos.mjs    # сверит пути, пропорции и mock/*.json
```

`fetch_photos.mjs` читает публичную страницу галереи, забирает сессионные
cookie и `sessionId`, затем дергает внутренний эндпоинт карт
`/maps/api/photos/getByBusinessId` (первый вызов отдаёт csrf-токен, второй —
список фото с размерами). Это неофициальный API: если Яндекс поменяет
вёрстку, скрипт упадёт с понятной ошибкой, а готовые файлы в
`assets/photos/shop/` продолжат работать.

## Соглашения

- Пропорции под слоты: hero ≈2.2:1, коллекции 16:10, товары 4:3, баннер 16:9.
- Прогрессивный JPEG q82, без EXIF, ширина ≤ 1400 px (исходники карт — 828–1280 px).
- Имена файлов = `id` товара/категории в данных, поэтому замена фото не требует
  правок в `js/api.js` и `mock/*.json` — достаточно положить файл с тем же именем.
- Фокус кадрирования (`JOBS` в `build_photos.py`) подбирается по снимку: у
  букетов оставляем цветы, у корзин и коробок — основание. Параметр `zoom`
  сужает кадр, когда в него попадает лишнее (например, ручка корзины).

Скриншоты в `previews/` — как слоты выглядят на страницах (`home.png`,
`catalog.png`, `product.png`).

## Права

Снимки загружены самой студией в свою карточку на Картах. Перед публичной
раскруткой стоит держать в проекте подтверждение прав (или перезалить
оригиналы из телефона владельца) — файлы легко заменить один к одному.
